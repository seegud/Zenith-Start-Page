## 一、高优先级问题

### 1.1 架构：单文件全部逻辑

**现状**：整个应用的所有逻辑（539 行）全部放在 `index.js` 中。SVG 图标、状态管理、UI 渲染、事件处理、API 调用混杂在一起，无任何模块化。

**问题影响**：
- 难以维护和定位代码
- 无法复用逻辑
- 多人协作时极易冲突
- 无法编写单元测试

**优化方案**：拆分为模块化结构：

```
src/
  icons.js          // SVG 图标定义
  state.js          // 全局状态管理
  weather.js        // 天气 API + 渲染
  wallpaper.js      // 壁纸 API + 渲染
  search.js         // 搜索逻辑
  clock.js          // 时钟逻辑
  settings.js       // 设置面板
  i18n.js           // 多语言
  utils.js          // 工具函数
  main.js           // 入口组装
```

---

### 1.2 空文件与无用配置

**现状**：
- `index.tsx` — 0 行空文件
- `tsconfig.json` 配置了 `"jsx": "react-jsx"`，但项目未使用 React
- `package.json` 安装了 `@types/node`，但这是纯前端项目

**优化方案**：
- 删除 `index.tsx`
- 移除 `@types/node` 依赖
- 将 `tsconfig.json` 中的 `jsx` 改为 `"preserve"` 或直接移除该配置

---

### 1.3 安全：第三方 CORS 代理

**现状**：Bing 壁纸 API 和天气 API 都通过 `https://corsproxy.io/?` 代理请求：

```javascript
const proxyUrl = 'https://corsproxy.io/?';
const bingApiUrl = 'https://www.bing.com/HPImageArchive.aspx?format=js&idx=0&n=1&mkt=en-US';
const res = await fetch(`${proxyUrl}${encodeURIComponent(bingApiUrl)}`);
```

**风险**：
- 第三方服务随时可能不可用
- 可能被限流或注入恶意内容
- 请求数据经过不可控的中间人

**优化方案**：使用 Vite 的开发代理 + 生产环境自建代理：

```typescript
// vite.config.ts
server: {
  proxy: {
    '/api/bing': {
      target: 'https://www.bing.com',
      changeOrigin: true,
      rewrite: (path) => path.replace(/^\/api\/bing/, ''),
    },
    '/api/weather': {
      target: 'https://wttr.in',
      changeOrigin: true,
      rewrite: (path) => path.replace(/^\/api\/weather/, ''),
    },
  },
}
```

生产环境可部署 Cloudflare Worker 或使用 Netlify/Vercel 的 rewrite 功能。

---

### 1.4 性能：Tailwind CDN 无摇树优化

**现状**：通过 CDN 加载 Tailwind CSS：

```html
<script src="https://cdn.tailwindcss.com"></script>
```

**问题**：
- CDN 版本包含完整的 Tailwind 编译器（~3MB）
- 每次页面加载都要重新扫描和编译样式
- 无摇树优化，所有 utility class 都被加载

**优化方案**：通过 npm 安装 Tailwind CSS，在构建时摇树：

```bash
npm install -D tailwindcss @tailwindcss/vite
```

然后在 `vite.config.ts` 中配置 PostCSS 插件，只打包实际用到的 CSS。

## 二、代码质量问题

### 2.1 内联 SVG 字符串过长

**现状**：`Icons` 对象和 `getWeatherIconHTML` 函数中有 **170+ 行** 硬编码的 SVG 字符串。

**优化方案**：
- 将每个 SVG 抽取为独立的 `.svg` 文件，用 Vite 的 `?raw` 导入
- 或使用 SVG sprite 方案，通过 `<use>` 引用
- 天气图标改用简洁的键值映射表

```javascript
// icons/weather.js
import Sun from './weather/sun.svg?raw';
import Cloud from './weather/cloud.svg?raw';

const WEATHER_ICONS = {
  113: Sun,
  116: Cloud,
  // ...
};
```

---

### 2.2 天气码硬编码与魔术数字

**现状**：数十个 wttr.in 天气码直接硬编码在多个 `if/else if` 条件中：

```javascript
else if ([143, 248, 260].includes(codeNum)) iconHTML = `...`;
else if ([179, 182, 227, 230, 317, 320, ...].includes(codeNum)) iconHTML = `...`;
```

**优化方案**：使用声明式映射表：

```javascript
const WEATHER_CODE_MAP = {
  CLEAR: [113],
  PARTLY_CLOUDY: [116],
  FOG: [143, 248, 260],
  THUNDER: [200, 201, 202, ...],
  SNOW: [179, 182, 227, 230, ...],
  RAIN: [176, 185, 263, 266, ...],
};

function getWeatherIcon(code) {
  for (const [type, codes] of Object.entries(WEATHER_CODE_MAP)) {
    if (codes.includes(parseInt(code, 10))) {
      return ICONS[type];
    }
  }
  return ICONS.DEFAULT;
}
```

---

### 2.3 DOM 操作无空值保护

**现状**：所有 `document.getElementById()` 调用都没有做 null 检查，HTML 结构变化时静默失败。

```javascript
const elements = {
  wallpaperBg: document.getElementById('wallpaper-bg'),
  // ...
};
elements.wallpaperBg.style.backgroundImage = `url(...)`; // 若为 null 则报错
```

**优化方案**：添加安全的 DOM 查询工具函数：

```javascript
function getElement(id) {
  const el = document.getElementById(id);
  if (!el) console.error(`Element #${id} not found`);
  return el;
}

// 或使用可选链
elements.wallpaperBg?.style?.setProperty('background-image', `url(...)`);
```

---

### 2.4 深层嵌套的 elements 对象

**现状**：约 50 行的四层嵌套结构，如 `elements.settings.wallpaperBlurSlider`。

**优化方案**：
- 按模块拆分 DOM 引用，每个模块管理自己的 DOM
- 或使用扁平化命名约定：`wallpaperBlurSlider`

## 三、性能优化

### 3.1 时钟忽略页面可见性

**现状**：即使标签页不可见，时钟仍在用 `setInterval` 每秒更新，浪费 CPU。

**优化方案**：监听页面可见性变化：

```javascript
let clockInterval;

function startClock() {
  renderClock();
  clockInterval = setInterval(renderClock, 1000);
}

function stopClock() {
  clearInterval(clockInterval);
}

document.addEventListener('visibilitychange', () => {
  if (document.hidden) stopClock();
  else startClock();
});

startClock();
```

---

### 3.2 搜索建议未取消前一个请求

**现状**：虽然使用了 `debounceTimeout` 延迟请求，但未取消上一个正在进行中的 fetch 请求，可能导致竞态条件。

**优化方案**：使用 `AbortController`：

```javascript
let abortController = null;

async function fetchSuggestions(query) {
  if (abortController) abortController.abort();
  abortController = new AbortController();
  
  try {
    const res = await fetch(url, { signal: abortController.signal });
    const data = await res.json();
    // 处理数据
  } catch (err) {
    if (err.name !== 'AbortError') console.error(err);
  }
}
```

---

### 3.3 壁纸无懒加载

**现状**：壁纸直接用 `background-image` 加载，无预加载提示，无分辨率适配。

**优化方案**：
- 使用 `<link rel="preload" as="image">` 预加载壁纸
- 考虑根据屏幕分辨率请求对应尺寸的壁纸
- 添加渐进式加载效果（先低分辨率再高清）

---

### 3.4 模糊滤镜实时计算

**现状**：每次拖动模糊滑块都触发 CSS `filter: blur()` 重绘。

**优化方案**：使用 `requestAnimationFrame` 节流，并添加 `will-change: filter`：

```css
#wallpaper-bg {
  will-change: filter;
}
```

```javascript
let blurRAF = null;
slider.addEventListener('input', (e) => {
  if (blurRAF) cancelAnimationFrame(blurRAF);
  blurRAF = requestAnimationFrame(() => {
    elements.wallpaperBg.style.filter = `blur(${e.target.value}px)`;
  });
});
```

## 四、可访问性

### 4.1 搜索建议不支持键盘导航

**现状**：搜索建议列表缺少以下 ARIA 属性：
- 无 `role="combobox"` 在输入框
- 无 `role="listbox"` 在建议容器
- 无 `role="option"` + `aria-selected` 在选项
- 无 `aria-activedescendant` 动态指定当前选项

**优化方案**：实现完整的 ARIA combobox 模式：

```html
<!-- 输入框 -->
<input role="combobox" aria-expanded="true" aria-haspopup="listbox" aria-activedescendant="suggestion-1" />

<!-- 建议列表 -->
<ul role="listbox">
  <li role="option" id="suggestion-0" aria-selected="false">...</li>
  <li role="option" id="suggestion-1" aria-selected="true">...</li>
</ul>
```

---

### 4.2 设置弹窗无焦点陷阱

**现状**：打开设置弹窗后，Tab 键能够聚焦到弹窗背后的元素。

**优化方案**：实现焦点循环：

```javascript
function trapFocus(modal) {
  const focusable = modal.querySelectorAll('button, input, [tabindex]:not([tabindex="-1"])');
  const first = focusable[0];
  const last = focusable[focusable.length - 1];
  
  modal.addEventListener('keydown', (e) => {
    if (e.key === 'Tab') {
      if (e.shiftKey && document.activeElement === first) {
        e.preventDefault();
        last.focus();
      } else if (!e.shiftKey && document.activeElement === last) {
        e.preventDefault();
        first.focus();
      }
    }
  });
  
  first.focus();
}
```

---

### 4.3 动态内容无 aria-live

**现状**：天气更新、时钟变化、加载状态等动态内容变化时，屏幕阅读器不会主动播报。

**优化方案**：为动态区域添加 `aria-live` 属性：

```html
<div id="weather-content" aria-live="polite" aria-atomic="true">
  <!-- 天气数据变化时自动播报 -->
</div>

<div id="clock-time" aria-live="polite" role="timer">
  <!-- 时钟更新时自动播报 -->
</div>
```

## 五、Service Worker 问题

### 5.1 无更新机制

**现状**：`sw.js` 没有 `skipWaiting()` + `clients.claim()` 更新策略，也没有通知用户更新的机制。用户可能永远停留在旧版本。

**优化方案**：

```javascript
// sw.js
self.addEventListener('message', (event) => {
  if (event.data === 'SKIP_WAITING') self.skipWaiting();
});

// main.js
if ('serviceWorker' in navigator) {
  navigator.serviceWorker.register('/sw.js').then(registration => {
    registration.addEventListener('updatefound', () => {
      const newWorker = registration.installing;
      newWorker.addEventListener('statechange', () => {
        if (newWorker.state === 'installed' && navigator.serviceWorker.controller) {
          // 提示用户刷新页面以获取新版本
          showUpdateBanner();
        }
      });
    });
  });
}
```

---

### 5.2 API 缓存无过期策略

**现状**：天气 API 响应被 Service Worker 缓存，但没有过期时间，用户可能看到过时数据。

**优化方案**：在 Service Worker 中为 API 请求设置 TTL（Time To Live），或使用 `Cache-Control` 响应头检查。

## 六、数据存储问题

### 6.1 localStorage 无容量管理

**现状**：
- 壁纸可能以 `data:image` 格式存储（可达数 MB），超出 localStorage 5-10MB 限制
- 搜索历史无限增长，无上限
- 无数据版本号和迁移机制

**优化方案**：
- 壁纸仅存储 URL，不使用 `data:image`
- 搜索历史限制最大条目数（如 50 条）
- 大体积数据（壁纸缩略图等）使用 IndexedDB
- 添加数据版本号实现向前兼容的迁移

```javascript
const STORAGE_VERSION = 1;

function migrateStorage() {
  const version = localStorage.getItem('storage_version');
  if (!version || parseInt(version) < STORAGE_VERSION) {
    // 执行迁移逻辑
    localStorage.setItem('storage_version', STORAGE_VERSION);
  }
}
```

---

### 6.2 无数据同步策略

**现状**：所有状态存储在 localStorage，多设备间无法同步。

**优化方案**（可选）：添加 JSON 导出/导入功能，让用户手动迁移设置：

```javascript
function exportSettings() {
  const data = {
    theme: state.theme,
    searchEngines: state.searchEngines,
    temperatureUnit: state.temperatureUnit,
    // ...
  };
  const blob = new Blob([JSON.stringify(data, null, 2)], { type: 'application/json' });
  const url = URL.createObjectURL(blob);
  // 触发下载
}
```

### 7.3 API 无重试与超时机制

**现状**：天气和壁纸 API 请求没有超时控制，也没有失败重试。

**优化方案**：封装带重试和超时的 fetch：

```javascript
async function fetchWithRetry(url, options = {}, retries = 3) {
  for (let i = 0; i < retries; i++) {
    try {
      const controller = new AbortController();
      const timeout = setTimeout(() => controller.abort(), 8000);
      const res = await fetch(url, {
        ...options,
        signal: controller.signal,
      });
      clearTimeout(timeout);
      if (!res.ok) throw new Error(`HTTP ${res.status}`);
      return res;
    } catch (err) {
      if (i === retries - 1) throw err;
      await new Promise((r) => setTimeout(r, 1000 * Math.pow(2, i)));
    }
  }
}
```

### 7.4 不支持多语言 i18n

**现状**：全部文本硬编码为英文，无国际化支持。

**优化方案**：引入简单的 i18n 方案：

```javascript
// i18n.js
const translations = {
  en: {
    search: 'Search the web or type a URL',
    settings: 'Settings',
    wallpaper: 'Wallpaper',
    uploadLocal: 'Upload Local',
    useBing: 'Use Bing Daily',
    // ...
  },
  zh: {
    search: '搜索网络或输入网址',
    settings: '设置',
    wallpaper: '壁纸',
    uploadLocal: '上传本地',
    useBing: '使用必应每日',
    // ...
  },
};

let currentLang = localStorage.getItem('lang') || navigator.language.slice(0, 2) || 'en';

export function t(key) {
  return translations[currentLang]?.[key] || translations.en[key] || key;
}

export function setLanguage(lang) {
  currentLang = lang;
  localStorage.setItem('lang', lang);
  // 重新渲染 UI
}
```

## 八、改进执行计划

建议按以下顺序分阶段实施：

| 阶段 | 任务 | 影响范围 |
|------|------|----------|
| **第一阶段** | 代码模块化拆分 + 清理无用文件 | 架构 |
| **第二阶段** | Tailwind CSS npm 版接入 + 摇树优化 | 性能 |
| **第三阶段** | Vite proxy 替代 corsproxy.io | 安全 |
| **第四阶段** | 添加 ESLint + Prettier | 工程化 |
| **第五阶段** | A11y 改善（键盘导航、焦点陷阱、ARIA） | 可访问性 |
| **第六阶段** | 性能优化（可见性、AbortController、重试） | 性能 |
| **第七阶段** | i18n 多语言支持 | 功能 |
| **第八阶段** | Service Worker 更新机制 + 缓存策略 | 离线体验 |

---

> 优先级从高到低排列，可根据实际情况调整执行顺序。
